\section{Funzioni e chiusure}
La programmazione in stile funzionale introduce il concetto di \textbf{funzioni di
  ordine superiore}. Si tratta di funzioni i cui parametri e/o il cui tipo di
ritorno sono a loro volta una funzione. Questo richiede, ad un linguaggio, la
possibilità di trattare una funzione come un tipo dati qualsiasi, consentendo di
memorizzarla in una variabile.

Rust offre vari modi di trattare il comportamento eseguibile come valore:
\begin{itemize}
  \item Puntatori a funzione di tipo \mintinline{rust}|fn(T1,...,Tn)->U|
  \item Chiusure, introdotte dalla sintassi lambda \mintinline{rust}|p1: T1, …, pn:Tn| -> R {…}|
  \item Parametri generici vincolati da tratti funzionali \verb|FnOnce|,
        \verb|FnMut|, \verb|Fn|.
\end{itemize}

La differenza chiave non è sintattica, ma semantica. I valori di tipo
\verb|fn(...)| non catturano stato. Le chiusure e i tipi derivati possono
includere uno stato catturato

La scelta del tipo di valore invocabile influenza vari aspetti: La
rappresentazione del valore, prestiti e possesso, modalità di invocazione,
possibilità di riuso.

\subsection{Puntatori a funzione - fn(T1, ..., Tn) -> U}
% Qualunque sia la natura del dato assegnato, si utilizza la variabile che contiene il puntatore come se fosse essa stessa una funzione.
% Sia il tipo di ritorno che tutti i tipi degli argomenti devono corrispondere a quanto dichiarato nella definizione della variabile (e della funzione).


Un valore di tipo \verb|fn(A, B) -> R| è un
puntatore a funzione con firma
compatibile. Può essere invocato come funzione
normale: \verb|f(x, y)|.


È adatto quando:

\begin{itemize}
  \item Il comportamento da eseguire è già definito
  \item Non serve catturare stato
\end{itemize}

\begin{center}
  \begin{minipage}{0.45\linewidth}
    \begin{minted}[breaklines]{rust}
fn f1(i: i32, d: f64) -> f64 { 
    return i as f64 * d; 
}

let ptr: fn(i32, f64) -> f64; 
ptr = f1; // assegno il puntatore 
ptr(2, 3.14); // chiamo la funzione 
\end{minted}
  \end{minipage}%
  \hfill
  \begin{minipage}{0.5\linewidth}
    \begin{minted}[breaklines]{rust}
fn add(a: i32, b: i32) -> i32 { a + b }
fn multiply(a: i32, b: i32) -> i32 { a * b }
fn choose(c: bool) -> fn(i32, i32) -> i32 {
  if c { add } else { multiply }
}
fn main() {
  let f1 = choose(true);
  let f2 = choose(false);
  println!("f1 => {}", f1(2, 3)); // 5
  println!("f2 => {}", f2(2, 3)); // 6
}
\end{minted}
  \end{minipage}
\end{center}


\begin{tcolorbox}
  \textbf{Nota:} \verb|fn(...)| rappresenta codice invocabile senza stato catturato
\end{tcolorbox}

\section{Chiusure: codice + ambiente catturato}
Un puntatore a funzione invoca solo codice; non incorpora un ambiente lessicale.
Una chiusura è un valore invocabile che può catturare variabili visibili nel
punto in cui è definita.
Le variabili catturate diventano parte dello stato della chiusura.
Ogni chiusura ha un tipo proprio, unico e anonimo generato dal compilatore.

Tale tipo implementa almeno il tratto \verb|FnOnce|, ed eventualmente anche
i tratti \verb|FnMut| e \verb|Fn|.


\begin{tcolorbox}
  \textbf{Note:} Una chiusura è simile ad una struct anonima con alcuni campi catturati
  e con un'operazione di chiamata definita dal compilatore
\end{tcolorbox}

\subsection{Differenza essenziale: una chiusura cattura l'ambiente}

\begin{flushleft}
  \begin{minipage}{0.45\linewidth}
    \raggedright
    \begin{itemize}
      \item \textbf{f\_ptr} non dispone di ambiente catturato, il suo
            risultato dipende solo dagli argomenti e da ciò che la funzione può già
            raggiungere senza cattura
      \item \textbf{closure(...)} usa anche \textbf{offset}, che appartiene al contesto lessicale esterno
      \item \textbf{offset} è una variabile libera nel corpo della chiusura
      \item Il compilatore decide come catturarla: per riferimento, come riferimento mutabile o per valore
    \end{itemize}

    \begin{tcolorbox}
      \textbf{Nota:} Una chiusura è una funzione accompagnata dal proprio ambiente
    \end{tcolorbox}

  \end{minipage}%
  \hfill
  \begin{minipage}{0.45\linewidth}
    \begin{minted}[breaklines]{rust}
fn add_one(x: i32) -> i32 {
  x + 1
}
fn main() {
  let offset = 10;
  let f_ptr: fn(i32)->i32 = add_one;
  let closure = |x| { x + offset };
  println!("{}", f_ptr(5)); // 6
  println!("{}", closure(5)); // 15
}
\end{minted}
  \end{minipage}
\end{flushleft}


\subsection{Chiusure che non catturano}
Una chiusura viene invocata come una funzione: \textbf{f(5)}.
Se \textbf{non cattura variabili}, può essere convertita a puntatore a funzione.
Se invece cattura un ambiente, la si descrive tramite:

\begin{itemize}
  \item \mintinline{rust}|impl Fn|
  \item \mintinline{rust}|impl FnMut|
  \item \mintinline{rust}|impl FnOnce|
\end{itemize}

Come oggetto tratto, \mintinline{rust}|Box<dyn Fn(...)>| quando occorre implementare
il dispatch dinamico.

\begin{center}
  \begin{minipage}{0.37\linewidth}
    \begin{minted}[breaklines]{rust}
fn ret_fun() -> fn(i32) -> i32 {
  |x|{ x + 1 }      //Funziona perché la funzione ritornata non cattura valori
}
\end{minted}
  \end{minipage}%
  \hfill
  \begin{minipage}{0.57\linewidth}
    \begin{minted}[breaklines]{rust}
fn ret_closure(i: i32) -> impl Fn(i32) -> i32 {
  move |x|{ x + i }   //viene catturata la variabile i
}
\end{minted}
  \end{minipage}
\end{center}


\subsection{Modalità di cattura in Rust}
Una chiusura cattura ogni variabile libera nel modo meno restrittivo compatibile
con il suo utilizzo nel corpo:

\begin{itemize}
  \item Se la variabile è solo letta, la cattura avviene tramite riferimento condiviso \verb|&|
  \item Se nel corpo richiede modifica dello stato catturato, la chiusura
        richiede accesso mutabile al proprio, \mintinline{rust}|let mut f = |...| {...};|
        e implementa tipicamente il tratto \verb|FnMut|
  \item Se il corpo consuma un valore catturato, la chiusura implementa il tratto \verb|FnOnce|
  \item Il borrow checker verifica la coerenza tra catture, prestiti e il
        tempo di vita
\end{itemize}

La parola chiave \verb|move| forza la cattura per valore: \mintinline{rust}{let f = move |...| {...};}.
\verb|move| non implica necessariamente \verb|FnOnce|.
Il tratto implementato dalla chiusura dipende da come il valore viene usato.

\subsection{Modello mentale: le chiusure come struct anonime}

\begin{flushleft}
  \begin{minipage}{0.5\linewidth}
    \raggedright
    Il compilatore materializza l'ambiente catturato come campi di un tipo
    anonimo

    \begin{itemize}
      \item Senza \verb|move|, la cattura può avvenire per riferimento
      \item Con \verb|move|, i campi dell'ambiente vengono catturati per
            valore
      \item l corpo della chiusura opera su questi campi
    \end{itemize}
  \end{minipage}%
  \hfill
  \begin{minipage}{0.45\linewidth}
    \begin{minted}[breaklines]{rust}
let y: Y = ...;
let z: Z = ...;
let f = |x| x + y.m() + z;  
//is equivalent to
struct __Closure<'a> {
  y: &'a Y,  // o Y o &mut Y in base all'uso nel corpo
  z: &'a Z, 
}
// impl Fn / FnMut / FnOnce for __Closure
   \end{minted}
  \end{minipage}
\end{flushleft}

\section{Fn}

\begin{center}
  \begin{minipage}{0.6\linewidth}
    Una chiusura di tipo \verb|Fn| accede all'ambiente catturato senza consumarlo né
    mutarlo, dunque può essere invocata più volte e produrrà sempre il medesimo risultato.

    Tipicamente, la cattura avviene tramite accesso in sola lettura al dato esterno.
    Questo è il caso più restrittivo ma anche quello più riusabile.
  \end{minipage}%
  \hfill
  \begin{minipage}{0.35\linewidth}
    \begin{minted}[breaklines]{rust}
let s = "hello"; 
let f = |v| v < s; 
f("world"); // false 
f("bye"); // true 
\end{minted}
  \end{minipage}
\end{center}





\section{Chiusure come argomenti}
Ogni chiusura ha un tipo anonimo distinto. Per accettare una chiusura come
parametro si usa spesso un \textbf{tipo generico}.

Il vincolo posto su tale tipo dipende dall'uso
previsto:

\begin{itemize}
  \item \verb|FnOnce|  se basta una chiamata
  \item \verb|FnMut| se si vuole modificare l'ambiente
  \item \verb|Fn| se vengono effettuate solo letture
\end{itemize}

La presenza del parametro generico dà origine
a \textbf{monomorfizzazione}. Se serve eterogeneità in fase di esecuzione, si
può usare \mintinline{rust}|Box<dyn Fn(...) -> R>|



% \section{Funzioni di ordine superiore}
% È possibile implementare una funzione che accetta come parametro una funzione lambda ricorrendo alla programmazione generica.
% Ogni funzione lambda forma infatti un tipo a sé, la cui unica istanza è la funzione lambda stessa. Tuttavia, esse implementano tutte almeno uno dei tratti funzionali: è quindi possibile definire una funzione generica che accetta come parametro di ingresso un'istanza del tipo F, soggetta al vincolo che tale tipo deve implementare uno dei tratti funzionali.

% Quale specifico tratto richiedere dipende dalla natura del codice che si intende scrivere:
% \begin{itemize}
%   \item \verb|FnOnce(Args)| accetterà qualsiasi chiusura, ma questa potrà essere invocata una sola volta.
%   \item \verb|FnMut(Args)| e \verb|Fn(Args)| sono via via più restrittivi sulle operazioni che è lecito eseguire all'interno della funzione e più ampi nell'uso della funzione di ordine superiore.
% \end{itemize}

\subsection{Restituire una chiusura in sicurezza}
% Analogamente, è possibile scrivere una funzione che restituisce una chiusura.
% Se la chiusura ritornata cattura qualche variabile, occorre fare attenzione al fatto che, normalmente, ciò implica memorizzare un riferimento all'interno della chiusura stessa. Questo fatto potrebbe imporre restrizioni sul tempo di vita del dato catturato non facilmente compatibili con il fatto che la chiusura ritornata deve sopravvivere alla funzione stessa (e quindi a tutte le sue variabili locali e ai suoi argomenti).

% In questa situazione, si usa comunemente il modificatore \mintinline{rust}|move| per trasferire il possesso di tali dati alla chiusura stessa.
% Può, inoltre, essere necessario richiedere che il dato catturato sia clonabile, se l'esecuzione della chiusura ritornata tendesse a consumare il dato e non si volesse ridurla ad \verb|FnOnce<Args>|.

Se una funzione restituisce una chiusura, il valore restituito deve essere
slegato dallo stack frame locale.

\begin{itemize}
  \item \mintinline{rust}|move| trasferisce il possesso dei valori alla chiusura
  \item \mintinline{rust}|impl Fn() -> T| nasconde il tipo anonimo concreto
        della chiusura
  \item L'invocazione del metodo \verb|clone| permette di restituire ogni volta
        un nuovo valore senza consumare quello catturato
\end{itemize}


\begin{minted}[breaklines]{rust}
fn value_source<T>(v: T) -> impl Fn() -> T where T: Clone { 
    return move || { v.clone() }; 
} 
\end{minted}

\begin{tcolorbox}
  \textbf{Note:} \textbf{move} serve spesso a rendere la chiusura restituita autosufficiente
\end{tcolorbox}


\subsection{Esempio di generatore}

Questa chiusura cattura \verb|b| per valore, e \verb|i|  per valore, mantenendolo
come stato interno mutabile.

Ad ogni invocazione lo stato si aggiorna e produce un risultato diverso.

Il tratto associato è \verb|FnMut|, perché l'ambiente viene modificato.
Questo pattern è utile quando si vuole incapsulare uno stato senza definire esplicitamente
una struct dedicata.

\begin{minted}[breaklines]{rust}
fn generator(prefix: &str) -> impl FnMut() -> String { 
    let mut i = 0; 
    let b = prefix.to_string(); 
    return move || { i += 1; format!("{}{}", b, i) } 
} 

fn main() {                                     // Output atteso:
    let mut f = generator("id_");               // id_1
    for _ in 1..5 {                             // id_2
        println!("{}", f());                    // id_3
    }                                           // id_4
} 
\end{minted}
